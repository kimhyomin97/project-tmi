# /learn — 학습 체크포인트

목표: AI가 내린 결정을 사용자가 **스스로 다시 내릴 수 있는지** 확인한다. 설명을 먼저 하지 않는다.

## 순서

1. 대상 범위를 정한다: 인자가 있으면 그 커밋/SPEC, 없으면 마지막 `feat:` 커밋. `git log -1 --format=%B <커밋>`의 `Learn:` trailer와 `git show --stat`을 읽는다.
2. trailer의 L번호마다 질문을 1개씩, 최대 3개 만든다. 질문은 **이 저장소의 실제 파일**을 가리키고 답이 갈릴 수 있게 쓴다.
   - L1 예: "`src/components/nav-link.tsx`는 왜 client여야 하고, `app-sidebar.tsx`는 왜 server로 남을 수 있나요?"
   - L3 예: "사이드바 접힘은 Zustand, 모바일 서랍 열림은 useState입니다. 둘을 바꾸면 무엇이 깨지나요?"
   - L4 예: "채점 결과를 저장한 뒤 목록이 바로 바뀌려면 어떤 키를 무효화해야 하나요? 더 넓게/좁게 잡으면 각각 무슨 일이 생기나요?"
   - L5 예: "BE가 꺼져 있을 때 이 화면은 어떤 모양이어야 하나요? `error.tsx`가 그걸 대신할 수 없는 이유는?"
3. 질문만 보여주고 사용자의 답을 기다린다. **정답·힌트를 먼저 말하지 않는다.**
4. 답을 받으면 질문마다 `맞음 / 부분 / 다름`으로 판정하고, 근거를 `파일:줄`로 2~3줄 보충한다. 사용자의 답이 코드보다 나은 판단이면 그렇게 말하고 개선 제안을 남긴다.
5. `docs/learning/log.md` 표 끝에 질문마다 한 줄을 추가한다: 날짜 | L번호 | 질문 요약 | 사용자 답 요약 | 판정 | 근거(파일:줄).
6. 같은 L번호에서 `다름`이 2번 연속이면 다음 plan의 ② 항목에 그 L번호 설명을 평소보다 자세히 쓰라고 SPEC에 메모한다.

## 하지 않는 것

- 코드를 고치지 않는다.
- 로그 외 파일을 만들지 않는다. 커밋은 일반 규칙(사용자 확인)을 따른다.

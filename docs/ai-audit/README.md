# FE AI 개발 환경·구조 점검 — 요약

대상: `main` `86e86bf`(2026-10-05). 작업 브랜치 `ai-audit/fe-audit`. 지시서: [`TASK.md`](./TASK.md). 기존 코드·설정은 바꾸지 않았다(산출물은 모두 `docs/ai-audit/` 아래).

## 핵심 발견 5개

1. **하네스는 정교하지만, 프로젝트 목표(사람의 FE 판단 체득)를 확인하는 장치가 없다.** 사람의 역할은 승인·증거 확인뿐이고 학습 흔적은 AI가 쓴 `Learn:` trailer 4줄이다. L5 결정(에러 경계)이 있었던 커밋 2개에는 trailer도 빠졌다. → [01 AI-01](./01-ai-setup.md)
2. **규칙은 7일 동안 10번 바뀌었고 데이터 기능은 0개다.** CLAUDE.md 변경 커밋 10개가 2026-09-28~10-04에 몰렸다. BE를 부르는 화면이 없어 L4(queryKey), L5 중 `useQuery` 3상태, BE 계약 규칙은 한 번도 시험받지 않았다. → [01 AI-02](./01-ai-setup.md), 제안 P-A2(동결)
3. **배포 전 막아야 할 구조 위험: 인증 없이 `/api/v1/*` 전체가 core로 중계된다.** VM을 공개하는 순간 core API(토스 자산 데이터 예정)가 인터넷에 열린다. → [03 CS-01](./03-code-structure.md), D-01
4. **확인 없이 실행되는 파괴 명령이 있다.** `git switch --discard-changes`·`-f`·`-C main`, `git branch -D <아카이브>`는 allow 목록에 있고 가드도 통과해, 기본 권한 모드에서도 사용자 워킹트리 변경이나 로컬 브랜치를 지울 수 있다(실측). 가드의 삭제 차단은 원격에만 걸린다. → [01 AI-04](./01-ai-setup.md), P-A5·D-09
5. **디자인 토큰 위반은 0건이지만, 토큰이 정하지 않은 영역과 첫 데이터 기능의 계약이 비어 있다.** 같은 "준비 중"이 두 모양(DS-01), 타이포 역할 미정의(DS-04), 404를 빈 상태로 바꿀 위치 미정(현재는 실패 화면이 됨, CS-04), 테스트 0(CS-02). → [02](./02-design-system.md), [03](./03-code-structure.md)

잘 되어 있는 것(유지 권장): 모든 문자열을 검사하는 디자인 토큰 lint와 `noInlineConfig`, untracked까지 보는 Stop hook, Server/Client 경계(client 파일 6개 모두 말단), rewrites로 BE 주소·CORS 문제 제거.
